# 可见历史归档

这里保存经核实的旧方案、旧实现和过程证据，供查找来源与理解变更。归档内容默认是**历史证据**，不作为当前产品规范、运行入口或已验收结论。当前入口见[项目首页](../README.md)、[文档导航](../docs/README.md)与[模块地图](../docs/architecture/README.md)。

已完成以下三个核实批次，逐文件来源、效力、处理和哈希见[批次索引目录](indexes/README.md)：[05 旧原型与阶段文档](indexes/05-prototype-documents.md)、[06 运维、发布与测试材料](indexes/06-operations-and-test-materials.md)、[07 旧源码与工具资料](indexes/07-source-and-tools.md)。它们覆盖 204 份归档文件；旧根、私有资料和未核实历史分支仍按[来源清单](../docs/development/source-inventory.md)保留，不能理解为所有本机资料均已归档。[基线记录](../docs/development/baselines.md)继续保留注明效力的历史正文。

## 稳定目录与分批索引

归档资料按用途放入 `archive/documents/`（旧文档）、`archive/implementations/`（旧实现）、`archive/evidence/`（过程证据）；目录在有实际内容时再创建。内部可按阶段分组并保留原相对路径，不能仅按日期判断资料是否失效。

各批在 `archive/indexes/` 维护自己的 Markdown 索引，使用两位任务编号与用途，互不争用一张大表。每个索引包含该批迁移的全部条目，能从相对链接打开归档文件和现行替代入口；没有替代时写明原因并链接当前模块导航。新增批次继续遵循以下约定。

## 每个条目的必填信息

| 字段 | 记录要求 |
| --- | --- |
| 归档位置 | 可打开的相对链接；每份材料都要可定位，成组目录另列逐文件清单 |
| 原位置 | 迁移前的仓库相对路径；不写本机私有绝对目录 |
| 来源版本 | 完整 commit / tag；未提交资料记原工作树身份、采样时间、内容 SHA-256 和保全证据的可公开摘要，不能冒称属于该 HEAD |
| 原用途与效力 | 当时服务哪个阶段、组件或用户任务；明确是旧约束、目标、报告还是实现 |
| 归档原因 | 说明已核实的实现/版本关系、替代或停止使用原因；不以文件名、日期、未跟踪状态作为唯一理由 |
| 现行替代入口 | 可打开的当前说明或源码；若仅保留证据、没有功能替代，明确标注并链接当前模块导航 |
| 内容处理 | 是否逐字保留、修复哪些引用、是否有脱敏/重排；记录迁移前后 SHA-256，变更时解释差异 |
| 验证与未完成项 | 实际检查、仍缺失的引用或验收；旧报告中的未通过与未执行不得改成通过 |

条目可采用表格或逐条小节，字段含义保持一致。多文件共用来源与原因时可在组头说明，逐文件清单仍需给出原路径、归档位置和哈希。归档文档开头标注历史效力、来源与现行入口；移动后同步修正有效引用，原始内容有调整必须可追溯。

## 迁移边界

移动前核实入站引用、脚本与构建发现范围；Agent、Web 辅助路径、根迁移目录、品牌资源和活动工具依赖不能仅凭“旧”整体归档。旧源码要与现行构建、测试、部署发现范围分离，避免产生第二个运行入口。

凭据、本机私有配置、设备原始日志、依赖缓存、生成协议、构建产物和 Git 内部数据不进入公开归档；保持本地保全策略，见[来源与恢复边界](../docs/development/source-inventory.md)。公开条目只保留足够的来源摘要，不链接本地检查点的绝对路径。迁移前重新核对内容与来源，保留可恢复依据；不能用本目录替代保全或用户验收。

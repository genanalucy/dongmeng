# 翻译会话授权接入契约

> 状态：目标接入契约（MVP）
>
> 适用组件：Cloud API、Translator Agent、Web / Android 客户端
>
> 范围：短期 translation session JWT 的签发、传递、验证、消费与结束
>
> 非目标：Access / Refresh Token、Provider 鉴权、PCM / 字幕业务协议

## 1. 目的与安全边界

Cloud API 是账号、权益和翻译会话授权的唯一权威；Translator Agent 是实时音频数据面，只消费 Cloud API 签发的一次性授权，不自行创建权益或信任客户端声明。

```text
Client --HTTPS + access token--> Cloud API
Client <--session_id + translation_token + wss_url-- Cloud API
Client --WSS + 首个 authorize/start 消息--> Translator Agent
Translator Agent --服务身份 + 原子 consume--> Cloud API internal API
Translator Agent <--> Provider
Translator Agent --服务身份 + finish--> Cloud API internal API
```

安全原则：

- translation token 是短期、单会话、单次消费的 bearer credential；不是 Access Token。
- Provider 凭据只存在服务端，且不属于本契约。
- Origin allowlist 只是浏览器纵深防御，不能替代 JWT 验证。
- JWT 验证成功只证明签名与声明有效；原子 consume 成功才允许启动上游会话。
- 授权完成前不得连接 Provider、接收 PCM、创建音频队列或记录用量。
- token、签名材料和完整 Authorization 值不得进入 URL、日志、指标、追踪或错误响应。

## 2. 当前实现与目标差异

当前 Cloud API 已通过 `POST /v1/translation-sessions` 创建约 5 分钟会话并签发 HS256 JWT，包含 `sub`、`jti`、`session_id`、`entitlement_id` 和 `scope=translation`。当前 Translator Agent 只校验 WebSocket Origin 和 `start` 结构，不验证或消费该 JWT。

本契约要求的目标状态：

1. translation JWT 使用非对称 `EdDSA`（Ed25519）签名；Cloud API 仅持签名私钥，Agent 仅持公钥。
2. translation token 使用独立 `iss`、`aud`、key set 和验证器，不与 access token 混用。
3. Agent 在现有 `start` 首包中验证 token，并经 Cloud API 原子 consume 后才启动 Provider。
4. 同一 `jti/session_id` 只允许一个连接消费；JWT 重放和并发连接均失败关闭。
5. Agent 在正常结束、超时和异常断开时向 Cloud API best-effort 上报终态。

过渡期兼容只允许在受控测试环境开启，并须有明确删除日期；生产环境不得长期同时接受 HS256 与 EdDSA。

## 3. 会话创建接口

### 3.1 请求

```http
POST /v1/translation-sessions
Authorization: Bearer <access_token>
Content-Type: application/json

{}
```

Cloud API 必须在同一业务流程中：

1. 鉴别当前用户；
2. 查询当前有效 entitlement；
3. 计算授权截止时间；
4. 持久化 session 与唯一 `jti`；
5. 签发 translation JWT。

### 3.2 成功响应

```json
{
  "session_id": "018f0000-0000-7000-8000-000000000001",
  "translation_token": "<redacted>",
  "token_type": "Bearer",
  "expires_at": "2026-01-01T00:05:00Z",
  "wss_url": "wss://agent.example.invalid/ws/translate"
}
```

约束：

- 响应必须使用 `Cache-Control: no-store`。
- `wss_url` 由服务端配置生成，客户端不得根据不可信输入拼接。
- 可在迁移期临时保留现有响应字段 `token`，但客户端切换完成后统一为 `translation_token`。
- `expires_at` 是“最迟开始授权”的截止时间，不代表连接可无限运行。
- entitlement 不存在或已过期时返回 `403 entitlement_required`，不得创建 session。

## 4. JWT 保护头与签名

目标 JOSE header：

```json
{
  "alg": "EdDSA",
  "typ": "JWT",
  "kid": "translation-2026-01"
}
```

| 项 | 契约 |
|---|---|
| 算法 | 仅允许 `EdDSA` / Ed25519；拒绝 `none`、HS256 及 header 指定的其他算法 |
| `kid` | 必填；只能在 Agent 预配置的 translation 公钥集合中查找 |
| 私钥 | 仅 Cloud API 签发端可访问，不下发给 Agent 或客户端 |
| 公钥 | 通过受控部署配置或固定 HTTPS JWKS 分发；未知 `kid` fail closed |
| 轮换 | 先发布新公钥，再用新私钥签发；旧公钥至少保留“最大 token TTL + 时钟偏差” |

禁止根据 token 内的 `jku`、`x5u` 或任意 URL 动态下载验证密钥，避免 SSRF 和不可信 key substitution。MVP 推荐部署时分发公钥；采用 JWKS 时必须固定 HTTPS 地址、限制响应大小和缓存时间，并在刷新失败时拒绝未知 `kid`。

## 5. Claims 契约

示例仅表示结构，不包含真实 token 或密钥：

```json
{
  "iss": "https://api.example.invalid/translation-auth",
  "aud": ["translator-agent"],
  "sub": "018f0000-0000-7000-8000-000000000010",
  "jti": "018f0000-0000-7000-8000-000000000020",
  "iat": 1767225600,
  "nbf": 1767225600,
  "exp": 1767225900,
  "scope": "translation",
  "session_id": "018f0000-0000-7000-8000-000000000001",
  "entitlement_id": "018f0000-0000-7000-8000-000000000030"
}
```

| Claim | 必填 | 语义与验证规则 |
|---|---:|---|
| `iss` | 是 | 固定等于 Agent 配置的 translation issuer；精确字符串比较 |
| `aud` | 是 | 必须包含且只允许目标 audience `translator-agent`；不得复用 access-token audience |
| `sub` | 是 | Cloud API 用户 UUID；必须可解析，且与 session 持久化归属一致 |
| `jti` | 是 | token UUID；全局唯一，是单次消费和重放检测键 |
| `iat` | 是 | 签发时间；不得明显晚于 Agent 当前时间 |
| `nbf` | 是 | 最早生效时间；建议等于 `iat` |
| `exp` | 是 | 授权开始截止时间；严格晚于当前时间 |
| `scope` | 是 | 必须精确等于 `translation`，不能使用子串或前缀匹配 |
| `session_id` | 是 | 翻译 session UUID；必须与首包 `sessionId` 完全一致 |
| `entitlement_id` | 是 | 签发时使用的 entitlement UUID；consume 时复核归属和有效期 |

禁止把 email、手机号、角色、Provider 名称、Provider 凭据或不必要的个人数据放入 translation token。

## 6. 时间与最长寿命

- token 最长寿命：`exp - iat <= 5 minutes`。
- 实际 `exp = min(iat + 5 minutes, entitlement.expires_at)`。
- `iat`、`nbf`、`exp` 使用 NumericDate（UTC 秒）。
- Agent 验证时钟偏差最多 `30 seconds`；偏差只用于 `iat/nbf` 容忍，已到 `exp` 的 token 不接受。
- Agent 与 Cloud API 主机必须启用可靠时钟同步；发现偏差超阈值应告警。
- consume 成功后的实时连接默认最长 `30 minutes`，并且不得晚于 entitlement 到期时间；到达较早截止点时 Agent 主动结束。
- 延长会话必须创建新的 session/token 和新连接；MVP 不支持在原连接内续 token。

5 分钟 token TTL 限制“何时可以开始”，30 分钟连接上限限制“授权后最多运行多久”，两者不得混淆。

## 7. Token 传递方式

### 7.1 浏览器与统一客户端方式

正式环境仅使用 `wss://`。为避免 query string 被代理、历史或日志记录，token 放在 WebSocket 建立后的首个文本消息中：

```json
{
  "type": "start",
  "sessionId": "018f0000-0000-7000-8000-000000000001",
  "translationToken": "<redacted>",
  "mode": "s2s",
  "sourceLanguage": "zh",
  "targetLanguage": "en",
  "targetAudioFormat": "pcm",
  "targetAudioRate": 16000
}
```

这是对现有 Agent `start` 消息的最小扩展。`translationToken` 必填且只允许一个紧凑 JWS 字符串；服务端应限制首包总大小（建议 `<= 8 KiB`）并继续拒绝未知字段。

### 7.2 禁止方式

- 禁止 `wss://.../ws/translate?token=...`。
- 禁止 cookie、URL fragment、自定义 WebSocket subprotocol 承载 bearer token。
- 禁止在客户端持久化 translation token；只保存在创建连接所需的短期内存中。
- 禁止把 Access Token 当 translation token 传给 Agent。

原生客户端虽然可以在 WebSocket HTTP 握手使用 `Authorization` header，但 MVP 统一采用首包，避免两套验证路径产生行为差异。

## 8. Agent 验证顺序

Agent 必须按下列顺序 fail closed；任一步失败都不得触达 Provider：

1. **HTTP/WSS 前置**：要求生产 WSS；校验请求方法、Host/路由、连接限额和浏览器 Origin allowlist。
2. **首包超时**：连接建立后最多等待 `10 seconds`；超时即关闭。
3. **消息外形**：首包必须是文本、JSON 单值、大小受限、无未知/重复字段；校验现有 `start` 字段。
4. **JWT 外形**：要求三段紧凑 JWS、长度受限；解析失败不回显 token。
5. **header 固定**：`typ=JWT`、`alg=EdDSA`、`kid` 已知；拒绝其他算法和 token 自带密钥 URL。
6. **签名验证**：使用 `kid` 对应的 translation 公钥验证；先验签，后信任 claims。
7. **标准 claims**：精确校验 `iss`、`aud`、`sub`、`jti`、`iat`、`nbf`、`exp`。
8. **业务 claims**：精确校验 `scope=translation`、UUID 格式及 `session_id == start.sessionId`。
9. **原子 consume**：Agent 使用服务身份调用 Cloud API internal consume；Cloud API 在事务中锁定 session，复核所有 claims、用户/权益归属、未消费状态和有效期，然后原子写入 `consumed_at`、Agent 实例/连接标识。
10. **资源分配**：consume 成功后才连接 Provider、创建 PCM 队列，并向客户端发送 `ready`。

不得只依赖本地 JWT 校验跳过 consume。若 consume 服务不可用或结果不确定，必须拒绝启动；不能为了可用性降级为“只验签”。

## 9. Internal consume 与服务认证

建议内部接口（不对普通客户端暴露）：

```http
POST /internal/v1/translation-sessions/{session_id}/consume
Authorization: <service identity>
Content-Type: application/json

{
  "jti": "018f0000-0000-7000-8000-000000000020",
  "user_id": "018f0000-0000-7000-8000-000000000010",
  "entitlement_id": "018f0000-0000-7000-8000-000000000030",
  "connection_id": "agent-generated-opaque-id"
}
```

服务认证优先使用 mTLS 或云 workload identity；若 MVP 使用独立 service token，该 token 必须与用户 JWT 分离、短期轮换、只授予 consume/finish 权限且不得写入日志。

原子 consume 事务必须保证：

- session 存在且数据库中的 `jti/user_id/entitlement_id` 与已验签 claims 完全一致；
- session 未消费、未结束、未撤销且未过授权开始截止时间；
- entitlement 属于同一用户，且 consume 时仍有效；
- 条件更新只影响一行；零行即失败，不允许 read-then-write 竞态；
- 成功响应返回 `connection_deadline = min(consumed_at + 30 minutes, entitlement.expires_at)`。

Cloud API 不接收完整 JWT；Agent 只发送验签后的标识字段，减少 bearer credential 扩散。

## 10. 错误码与拒绝策略

### 10.1 WebSocket 授权错误

Agent 在可安全写响应时发送统一结构，随后关闭连接：

```json
{
  "type": "error",
  "code": "TRANSLATION_AUTH_INVALID",
  "message": "translation authorization failed"
}
```

| Code | 场景 | 是否可重试 |
|---|---|---|
| `TRANSLATION_AUTH_REQUIRED` | 首包缺少 translation token | 获取 token 后新建连接 |
| `TRANSLATION_AUTH_INVALID` | JWT 格式、算法、签名、issuer、audience、scope 或 claims 无效 | 不使用原 token重试 |
| `TRANSLATION_AUTH_EXPIRED` | token 已到期或超过最长 TTL | 向 Cloud API 新建 session |
| `TRANSLATION_AUTH_MISMATCH` | `session_id` 与首包或持久化记录不一致 | 不使用原 token重试 |
| `TRANSLATION_AUTH_REPLAYED` | session / `jti` 已消费、结束或并发竞争失败 | 新建 session；不得复用 |
| `TRANSLATION_AUTH_FORBIDDEN` | 用户/权益归属错误、权益失效或 session 被撤销 | 重新查询权益，不盲目重试 |
| `TRANSLATION_AUTH_UNAVAILABLE` | key/consume 服务不可用或结果不确定 | 指数退避后创建新 session |
| `TRANSLATION_SESSION_LIMIT` | 用户/IP/实例并发上限 | 等待已有会话结束后重试 |

对外 `message` 保持通用，不披露签名失败细节、内部状态、数据库信息或 key id 清单。详细失败原因只记为受控枚举指标，不记录 token；同一 IP、用户和 `jti` 的失败应限流。

### 10.2 关闭策略

- HTTP 握手阶段可确定的 Origin、路由或容量错误：拒绝 upgrade，使用 `403` 或 `429`。
- upgrade 后授权失败：发送一个 error event，再以 WebSocket policy violation 类关闭码（建议 `1008`）关闭。
- malformed / 超大首包：不解析后续消息，立即关闭。
- 授权前收到 binary PCM：返回 `TRANSLATION_AUTH_REQUIRED` 并关闭，绝不缓存。
- 未知 `kid`、JWKS 不可用、consume 超时或数据库错误：fail closed。
- 客户端不得在同一 WebSocket 内替换 token 或重新授权；重试必须新建 session 和连接。

## 11. 重放、并发与重连

- 唯一性键为持久化的 `jti`，并与唯一 `session_id` 一一绑定。
- session 状态至少包含：`issued -> consumed -> finished`，另允许 `expired/revoked/failed` 终态。
- consume 使用单条条件 UPDATE 或行锁事务；只有一个竞争请求能从 `issued` 转为 `consumed`。
- 同一 token 同时连接多个 Agent 时，首个成功 consume 的连接获准，其余返回 `TRANSLATION_AUTH_REPLAYED`。
- Agent 本地缓存只能作为快速拒绝层，不能替代数据库权威状态。
- 客户端网络断开后不得复用旧 token；应请求新 session。旧连接由 Agent 结束并上报。
- MVP 不做“同一 session 断点重连”，避免双活连接、音频乱序和重复用量。
- 可按用户施加活动会话上限；上限判定以 Cloud API 权威状态为准，并处理 Agent 崩溃后的租约超时。

重放失败响应不得暴露原连接位置或用户信息。重复 consume 不能把授权从既有连接转移给新连接。

## 12. 会话结束与终态上报

正常流程沿用现有客户端 `{ "type": "finish" }`：

1. Agent 停止接受新 PCM 并排空受限队列；
2. Agent 调用 Provider finish，并等待其终态或本地超时；
3. Agent 向客户端发送 `finished`；
4. Agent 使用服务身份调用 Cloud API internal finish，幂等写入终态与权威 usage；
5. Agent 关闭连接并释放所有资源。

异常断开、Provider 错误、Agent 超时、达到 `connection_deadline`、服务关闭时，也必须 best-effort 上报 finish，至少包含：

```json
{
  "connection_id": "agent-generated-opaque-id",
  "reason": "client_disconnect",
  "audio_seconds": 120,
  "characters": 300
}
```

约束：

- finish 接口以 `session_id + connection_id` 幂等；重复请求返回既有结果。
- 只有成功 consume 的连接可 finish；connection 不匹配则拒绝。
- `reason` 使用固定枚举，如 `completed`、`client_disconnect`、`deadline`、`provider_error`、`agent_shutdown`。
- usage 由 Agent 测量并通过内部接口上报；客户端数据不得作为权威计费依据。
- finish 上报失败不能延长连接；Agent 关闭资源并重试有限次数，Cloud API 通过租约/清理任务终结遗留 `consumed` session。
- 达到截止时间时先停止接收 PCM，再以超时终态关闭；不得继续使用已失效 entitlement。

## 13. 日志、指标与审计

允许记录：截断/散列后的 session 标识、Agent 实例、固定错误码、阶段耗时、consume 结果、连接时长和聚合 usage。

禁止记录：

- 完整 JWT、JWT 任一完整段、Authorization header；
- 签名私钥、公钥原文转储、service credential；
- Provider credential、PCM、字幕正文或用户 email；
- 包含 token 的请求体、URL、panic dump 或 tracing baggage。

建议指标：授权成功率、按错误码拒绝数、consume 延迟、重放次数、首包超时数、活动连接数、deadline 结束数、finish 上报失败数。对异常重放和未知 `kid` 告警，但避免把攻击者输入作为无限基数 label。

## 14. 迁移顺序

### 阶段 0：契约与数据准备

- 固化独立 translation `iss/aud`、5 分钟 TTL、30 秒偏差和 30 分钟连接上限。
- 为 session 增加状态、`consumed_at`、`finished_at`、`connection_id`、终态原因等持久化能力。
- 定义 internal consume/finish 服务认证、幂等和监控。

### 阶段 1：Cloud API 双签测试

- 引入 Ed25519 key set 和 `kid`，先分发公钥到 Agent 测试环境。
- Cloud API 测试环境签发 EdDSA translation token；access token 逻辑保持独立。
- `exp` 截断到 entitlement 到期时间，并补齐 `nbf` 与独立 audience。

### 阶段 2：Agent 验证但不触达生产流量

- 扩展现有 `start` 消息增加 `translationToken`。
- 实现严格本地验证和 internal consume；所有失败均发生在 Provider 连接之前。
- 用测试流量验证错误码、限流、日志脱敏、并发竞争和 key 轮换。

### 阶段 3：客户端切换

- 客户端先调用 Cloud API 创建 session，再以首包携带 token 连接 Agent。
- Web、Android 分批启用；观察授权失败率与 consume 延迟。
- 客户端不再直连无授权 Agent，也不持久化 translation token。

### 阶段 4：强制与清理

- 生产 Agent 强制要求 EdDSA translation token 和 consume 成功。
- 删除未授权兼容路径及任何临时 HS256 translation 验证开关。
- 删除旧响应字段 `token`（经过版本兼容窗口后），保留稳定的 `translation_token`。
- 完成故障演练、回滚边界确认和安全复核。

回滚只能回滚客户端流量版本或停止新会话，不能回滚到“无授权即可连接 Provider”。

## 15. 验收清单

### 签发

- [ ] 无有效 entitlement 无法创建 session。
- [ ] `iss/aud/scope` 使用 translation 专用固定值。
- [ ] 仅 EdDSA，header 有受信 `kid`，Agent 无签名私钥。
- [ ] 所有必需 claims 存在且 UUID/时间格式正确。
- [ ] `exp - iat <= 5 minutes`，且 `exp <= entitlement.expires_at`。
- [ ] 创建响应 `no-store`，token 不出现在 URL 或日志。

### 验证与拒绝

- [ ] 缺失、截断、篡改、错误算法、未知 `kid` 的 token 均在连接 Provider 前拒绝。
- [ ] 错误 `iss/aud/scope/sub/session_id/entitlement_id` 均被拒绝。
- [ ] 未来 `nbf`、过期 `exp`、超长 TTL 和超时首包均被拒绝。
- [ ] Agent 严格按“验签 -> claims -> consume -> Provider”顺序执行。
- [ ] consume 不可用时 fail closed，无“仅验签”降级。
- [ ] 授权前 PCM、第二次 start、同连接替换 token 均被拒绝。

### 重放与并发

- [ ] 同一 token 串行重放失败。
- [ ] 同一 token 两个并发连接只有一个 consume 成功。
- [ ] 不同用户的 session、entitlement、token 不能交叉组合。
- [ ] 断线后旧 token 不可重连；新 session 可正常建立。
- [ ] 用户/实例并发上限在多 Agent 实例下行为一致。

### 结束与运维

- [ ] 正常 finish、客户端断开、Provider 错误、deadline、Agent shutdown 均形成终态。
- [ ] finish 和 usage 上报幂等，且只接受成功 consume 的 connection。
- [ ] 遗留 consumed session 会由租约/清理任务终结。
- [ ] key 轮换期间新旧合法 token 可按窗口验证，窗口后旧 key 被拒绝。
- [ ] 日志、指标、trace、错误响应和代理访问日志中均无 token 或 credential。
- [ ] WSS、Origin allowlist、服务认证、限流和时钟同步已在生产配置验证。

## 16. 明确待实现项

# 言枢智能基础设施与第三方服务申请清单

> 文档版本：v1.0
> 用途：内测阶段资源申请、正式上线前资源采购与审批依据
> 产品：言枢智能（实时同传，智联世界）
> 更新时间：2026-08-24

## 1. 项目与申请背景

言枢智能是一款面向个人用户的实时语音翻译产品，支持 Web 与原生 Android 客户端，主要提供：

- 单人同传；
- 面对面双人翻译；
- 中文、英语、法语、越南语间的实时翻译；
- 实时字幕与译文语音播放；
- 注册试用、包装盒兑换码权益及后续耳机产品联动。

产品架构分为两部分：

```text
客户端（Web / Android）
        │ HTTPS / WSS
        ▼
Cloud API（控制面）
- 账号、登录、试用权益、兑换码
- 翻译会话授权、用量、审计
- 测试反馈数据索引与删除策略
        │ 短期翻译会话 Token
        ▼
Translator Agent（实时翻译数据面）
- PCM 音频流
- 实时字幕、TTS
- 火山引擎 / 阿里云百炼 Provider 路由
        │
        ▼
第三方实时翻译服务
```

安全原则：

- 第三方翻译 Provider 的 API Key 仅保留在服务端 Secret 中，绝不下发到 Web、Android 或用户浏览器；
- 账号、权益和用量由 Cloud API 统一控制；
- 测试阶段如经用户明确同意，可保留反馈文本和音频索引 14 天；生产阶段默认不长期保留原始音频；
- 生产环境必须使用 HTTPS / WSS，不使用公开 HTTP/WS 作为正式入口。

## 2. 当前临时测试方案

当前开发与内测阶段，Cloud API 可先运行在开发机，通过现有测试服务器进行 SSH 隧道或反向代理转发：

```text
临时中转服务器：[旧环境地址已脱敏]
临时运维入口：ssh root@[旧环境地址已脱敏]
```

该方案仅用于开发联调和小范围内测，不应作为正式生产部署方案，原因包括：

- 服务依赖开发机在线；
- 当前公网转发不具备完整的生产鉴权、监控、备份与高可用能力；
- 不适合长期保存用户数据或承载大规模实时音频连接；
- 正式环境不应使用 root 账户作为日常部署账户。

### 临时方案最低安全要求

- 仅开放必要端口；
- 使用 SSH Key，禁止共享密码；
- 不在服务器、命令历史、日志或 Git 中保存 Provider API Key；
- Cloud API 与数据库凭据以环境变量或 Secret 文件注入，文件权限限制为 `600`；
- 测试入口明确标注“内测环境”，并限制测试用户范围；
- 在迁移正式服务器后关闭临时公网入口。

## 4. 正式域名与 DNS 申请

### 4.1 申请内容

申请一个可控的正式域名，并授予项目负责人员 DNS 记录管理权限。

建议子域名规划：

```text
app.<主域名>      Web 产品入口
api.<主域名>      Cloud API（账号、权益、授权）
agent.<主域名>    Translator Agent（实时翻译服务）
admin.<主域名>    后续管理后台
mail.<主域名>     邮件发信域名/邮件认证
```

### 4.2 用途与必要性

- 浏览器麦克风与部分移动端能力要求安全上下文，正式环境必须 HTTPS；
- 实时语音 WebSocket 必须使用 WSS；
- Android Release 版本应仅接受 HTTPS/WSS；
- 邮箱服务需要配置 SPF、DKIM、DMARC 等 DNS 记录；
- 域名可避免将 IP 地址直接暴露给用户并便于未来迁移服务器。

### 4.3 权限与安全要求

- DNS 控制台启用多因素认证；
- 仅授权必要人员编辑 DNS；
- 域名和证书自动续期；
- 所有生产 API 仅允许 TLS 1.2+；
- 不使用裸 IP 作为最终用户入口。

## 5. 新后端服务器申请

### 5.1 推荐规格

#### 内测/早期公测最低配置

```text
操作系统：Ubuntu 24.04 LTS 或 Debian 12
CPU：2 vCPU
内存：4 GB RAM
磁盘：60 GB SSD 起
公网 IPv4：1 个
带宽：5 Mbps 起
```

#### 建议的正式初期配置

若 Cloud API 和 Translator Agent 都部署在该服务器，建议：

```text
操作系统：Ubuntu 24.04 LTS 或 Debian 12
CPU：4 vCPU
内存：8 GB RAM
磁盘：100 GB SSD 起
公网 IPv4：1 个
带宽：10 Mbps 起，按真实并发持续评估
```

说明：实时翻译容量的关键指标是峰值并发翻译会话、音频时长和 Provider 限流，不只是注册用户数。服务器资源需结合压测与实际数据逐步扩容。

### 5.2 部署服务

```text
Caddy 或 Nginx              HTTPS/WSS 反向代理与证书续期
Cloud API                   账号、权益、会话授权、管理 API
Translator Agent            实时音频、字幕、TTS、Provider 路由
PostgreSQL 或数据库客户端    业务数据访问
后台清理任务                过期会话、14 天反馈数据清理调度
监控/日志 Agent             可用性、错误与资源指标采集
```

### 5.3 服务器安全基线

- 创建非 root 部署账户，例如 `deploy`；
- 日常部署使用 `deploy` + SSH Key，不使用 root；
- 禁用 SSH 密码登录，禁用 root 远程登录；
- 安全组仅开放：`22`、`80`、`443`；
- 数据库端口不对公网开放；
- 启用自动安全更新、基础防火墙和时钟同步；
- 生产服务运行账号最小权限化；
- 机密通过 Secret Manager、部署环境变量或权限 `600` 的本地 Secret 文件注入；
- 开启磁盘/快照加密能力（云厂商支持时）。

### 5.4 申请时需提供的信息

- 云厂商与区域；
- 新服务器公网 IP；
- SSH 公钥登录方式；
- 是否允许安装 Docker Engine 与 Docker Compose Plugin；
- 安全组编辑权限或运维协助窗口；
- 是否使用托管数据库或同机开发数据库。

> 不需要提供服务器密码、SSH 私钥或任何第三方 API Key。

## 6. PostgreSQL 16 数据库申请

### 6.1 建议方案

优先使用托管 PostgreSQL 16；早期内测如预算有限，可使用独立 Docker PostgreSQL，但需明确备份和迁移计划。

数据库保存：

```text
用户与登录身份
密码凭据哈希
Refresh Token 哈希
多设备安装记录
试用、兑换、订阅等权益记录
包装兑换码哈希及批次
翻译会话与用量记录
用户授权同意记录
测试反馈文本与音频对象索引
管理员操作审计记录
```

数据库不保存：

```text
密码明文
Access Token / Refresh Token 明文
兑换码明文
第三方 Provider API Key
实时 PCM 音频二进制
```

### 6.2 最低能力要求

```text
版本：PostgreSQL 16
字符集：UTF-8
时区：UTC
备份：每日自动备份，至少保留 7 天
监控：连接数、CPU、磁盘、慢查询、备份状态
网络：仅允许应用服务器私网/安全组访问
加密：传输加密 TLS，磁盘加密（若供应商支持）
```

### 6.3 初期容量建议

```text
CPU：2 vCPU 起
内存：4 GB RAM 起
存储：50 GB 起，可在线扩容
高可用：正式商业化前评估主备/跨可用区
```

## 7. 私有对象存储申请（测试音频反馈）

### 7.1 使用目的

在用户明确同意测试数据收集的前提下，临时保存用于故障定位、质量改进和用户反馈处理的音频文件。

数据保留规则：

```text
测试阶段：反馈文本和音频最长保留 14 天
到期后：自动删除对象及对应索引记录
正式阶段：默认不保存原始音频；如需保存须重新取得明确授权
```

### 7.2 推荐能力

```text
服务：阿里云 OSS、腾讯云 COS、Amazon S3、Cloudflare R2 等
Bucket：私有 Bucket，禁止公网读写
上传：由服务端签发短期预签名 URL
访问：仅后端受控访问，管理员访问须审计
生命周期：对象创建后 14 天自动删除
加密：服务端加密，传输 HTTPS
日志：开启访问日志或等效审计能力
```

### 7.3 数据边界

允许保存：

```text
加密/受控访问的测试音频对象
对象键（object key）
内容类型、大小、创建时间、过期时间
与用户同意版本关联的必要元数据
```

禁止保存：

```text
公开可访问音频链接
长期保留原始音频
未取得同意的用户音频
Provider API Key、密码、Token 等机密
```

### 7.4 申请信息

- 选择对象存储云厂商与区域；
- 创建私有 Bucket 的权限；
- 配置 14 天生命周期删除规则的权限；
- 创建最小权限服务账号/角色的权限；
- 开通预算告警与访问审计。

> AccessKey、SecretKey 等密钥无需通过聊天或文档提供；应直接配置到部署服务器的 Secret 管理中。

## 8. 手机短信验证码服务申请

### 8.1 建议范围

第一期建议仅支持中国大陆手机号：

```text
国家区号：+86
用途：注册 / 登录验证码
```

后续再根据用户来源评估国际短信。

### 8.2 推荐服务

优先考虑阿里云短信；也可根据现有云厂商生态选择腾讯云短信等。

### 8.3 需要提前完成的事项

- 企业/个人账号实名认证；
- 短信签名申请，例如：`言枢智能`；
- 短信模板申请；
- 短信发送预算与余额预警；
- 测试手机号白名单（如服务商支持）；
- 短信服务控制台访问权限。

建议申请模板：

```text
【言枢智能】验证码：${code}，5分钟内有效，请勿泄露给他人。
```

### 8.4 实施安全要求

```text
验证码有效期：5 分钟
单验证码使用次数：1 次
单手机号发送频率：限制
单 IP 发送频率：限制
验证失败次数：限制
生产日志：不记录验证码明文
开发环境：可使用受控 Stub，不调用真实短信服务
```

### 8.5 本轮状态

Cloud API 框架会预留手机号验证码接口与开发 Stub；真实短信服务在签名/模板审核完成后接入。

## 10. 翻译 Provider 生产环境准备

当前产品使用不同 Provider 覆盖不同语言方向。生产前应完成开发、预发布、生产环境隔离。

需准备：

```text
生产独立的阿里云百炼业务空间/凭据
生产独立的火山引擎凭据
开发、预发布、生产环境分别隔离
余额、预算和账单告警
模型限流额度确认
高峰期临时提额申请路径
Provider 服务状态监控
```

关键说明：

- 同一主账号下增加多个 API Key 通常不会自动增加总限流额度；
- 充值解决余额问题，不一定提高 RPM/TPM/并发限制；
- Provider Key 仅由服务端持有；
- 用户请求必须先经过 Cloud API 的权益、配额和会话授权检查；
- 用户量增加时应通过平台侧并发槽位、限流、排队、监控和官方提额处理，而不是将 Key 下发给客户端。

## 11. 监控、日志与告警申请

### 11.1 最低监控项目

```text
Cloud API 健康状态、响应时间、5xx 错误率
Translator Agent 连接数、会话创建成功率、断连率
Provider 错误率、限流响应、连接延迟
PostgreSQL CPU、连接数、存储、慢查询、备份状态
服务器 CPU、内存、磁盘、网络带宽
每用户/每语言方向使用时长与成本估算
对象存储容量、生命周期删除是否成功
```

### 11.2 告警建议

```text
服务不可用
错误率持续升高
Provider 429/限流或余额异常
数据库磁盘/连接数接近阈值
备份失败
对象存储 14 天清理任务失败
异常用量或单用户高频滥用
TLS 证书即将过期
```

日志要求：

- 不记录密码、验证码、Token、兑换码明文和 Provider Key；
- 日志访问需最小权限控制；
- 管理员查看用户反馈数据应保留审计记录；
- 调试日志不得长期保留敏感音频内容。

## 14. 分阶段申请建议

### 阶段 A：当前至内测（优先申请）

```text
1. 正式域名与 DNS 管理权限
2. 新后端服务器或明确云厂商/区域
3. PostgreSQL 16（托管或临时自建）
4. TLS/HTTPS/WSS 反向代理部署权限
5. 私有对象存储及 14 天生命周期规则
6. 监控、日志、备份基础能力
```

### 阶段 B：开放手机号和邮箱登录前

```text
1. 阿里云短信或等效服务的签名、模板、预算
2. 邮件服务、发信域名与 SPF/DKIM/DMARC
3. 用户协议、隐私政策、测试数据同意文案
4. 客服与用户数据删除处理流程
```

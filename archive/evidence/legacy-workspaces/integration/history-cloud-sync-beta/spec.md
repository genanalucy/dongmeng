# 测试版历史云端同步体验

## Problem Statement

测试版用户打开历史页时只看到本机历史副本。尽管已完成 Turn 会通过后台任务同步到云端历史副本，用户无法确认是否正在同步、是否已经拉取另一设备的历史，或为何页面显示“暂无本机记录”。这使跨设备同步看起来像未接入。

## Solution

在 Debug 内部测试版的历史页中，于已认证用户进入历史页时主动同步云端历史副本到本机历史副本；提供手动“立即同步”入口，并清晰显示同步中、成功、离线/失败及尚未同步状态。同步完成后，历史列表直接展示已写入本机历史副本的本机与云端会话。正式版现有历史页行为和文案不随本项改变。

## User Stories

1. As a Debug 内部测试版用户, I want 历史页打开后自动拉取云端历史副本, so that 我能在当前设备看到其他设备已完成的翻译会话。
2. As a Debug 内部测试版用户, I want 在历史页看到“正在同步”, so that 我知道空列表不是应用无响应。
3. As a Debug 内部测试版用户, I want 在历史页看到最近一次同步成功状态, so that 我能确认云端历史副本已被核验。
4. As a Debug 内部测试版用户, I want 在网络不可用或云端同步失败时看到明确失败状态, so that 我知道本机历史副本仍可离线查看且可稍后重试。
5. As a Debug 内部测试版用户, I want 点击“立即同步”, so that 我无需等待后台 WorkManager 调度即可拉取云端历史。
6. As a Debug 内部测试版用户, I want 同步完成后历史列表自动更新, so that 我不必退出或重新打开页面来看到云端会话。
7. As a Debug 内部测试版用户, I want 云端拉取结果继续保存为本机历史副本, so that 搜索、导出、重命名和删除仍在同一历史界面工作。
8. As a 已登录用户, I want 只同步当前账户的云端历史副本, so that 不同账户在同一设备上不会互相暴露历史。
9. As a 离线用户, I want 历史页继续展示已有本机历史副本, so that 网络问题不会阻止我阅读、搜索或导出历史。
10. As a 离线用户, I want 手动同步在恢复网络后可重试, so that 暂时失败不会丢失本机待同步写入。
11. As a 用户, I want 删除优先规则在主动同步后仍成立, so that 已删除翻译会话不会从另一设备的旧副本复活。
12. As a 用户, I want 历史配额状态继续由现有同步协议处理, so that 主动同步不会绕过历史配额保护。
13. As a 正式版用户, I want 现有历史界面保持不变, so that 测试中的同步诊断控件不会成为未验收的正式体验。
14. As a 无障碍用户, I want 同步状态和按钮具有可读语义, so that 我能获知同步进度并触发重试。
15. As a 测试人员, I want 能区分“云端没有历史”“尚未同步”“同步中”“同步失败”, so that 空状态可被准确验收。

## Implementation Decisions

- 范围限定为 Debug 内部测试版；以构建类型门控历史同步诊断 UI 和进入历史页的主动同步触发，Release 不展示新增入口或状态。
- 保留云端历史副本作为跨设备同步权威副本，本机历史副本作为离线可读、副本合并与待同步写入的位置；不增加第二套历史列表或绕过本机加密存储。
- 复用既有历史同步协议：先推送本机 outbox，再从云端 cursor 拉取所有增量页，并以既有删除优先合并规则写回本机历史副本。
- 在历史表现层引入面向用户的同步状态：未开始、同步中、已成功、失败；状态应包含可安全展示的摘要，不暴露认证信息、服务端错误原文、加密载荷或 cursor。
- 历史页首次加载当前已认证账户时触发一次主动同步；用户可从 Debug 测试版历史页手动再次触发。同步中重复触发应合并为单次进行中的同步，不能并发 push/pull 同一账户。
- 主动同步与现有 WorkManager 网络约束同步共享同一账户级互斥边界，防止后台任务和手动同步同时处理相同 outbox。
- 自动登录不存在或凭据失效时不调用云端历史接口；本机历史副本仍按现有账户隔离规则展示或清除。
- 空状态文案在 Debug 测试版须基于同步状态区分：无本机或云端会话、同步进行中、同步失败且保留本机副本；不得宣称云端内容已核验，除非本次同步成功。
- 不修改 Room schema、云端历史 API 契约、历史配额、加密格式或删除优先规则。

## Testing Decisions

- 最高测试缝为历史 ViewModel 对外暴露的同步状态与会话列表：给定认证账户和可控同步服务，验证进入历史页与手动操作造成的可观察状态转换和会话更新，而非断言 WorkManager 排队细节。
- 使用现有本机历史仓库/云端 history transport 抽象作为测试替身边界，覆盖：空云端成功、云端会话拉取成功、离线/服务失败、待上传 outbox、重复同步请求，以及当前账户切换期间的过期回调。
- 复用现有 HistoryViewModel 行为测试与 HistoryPage Compose 测试风格，验证 Debug 历史页的按钮可访问性、状态文案和列表刷新；Release 构建测试验证新增 Debug-only 控件不出现。
- 复用现有 Cloud API history sync 合同测试，确保客户端主动调用的 push/pull 顺序与 cursor 分页继续符合服务端契约。
- 好测试只断言用户可见的同步状态、列表内容和账户隔离结果，不断言具体 Worker 名称、DAO 调用次数或实现私有锁。

## Out of Scope

- 正式版历史页新增同步按钮、同步状态 UI 或文案改版。
- 新增或迁移数据库 schema。
- 新建云端历史 API、修改历史 payload 加密格式、修改服务端配额。
- 云端历史的实时推送、跨设备冲突策略重写、批量导入导出、历史恢复备份。
- 自动修复已无法解密的旧本机历史副本。

## Further Notes

生产 Cloud API 已启用历史同步路由。当前问题是客户端历史页只观察本机历史副本，且同步主要由完成 Turn 后的 WorkManager 触发；本规格将主动拉取与可观察状态添加到 Debug 内部测试版，以便真机验收跨设备历史同步。

# 邮箱验证码注册与自建 SMTP 设计

**状态：** 已确认设计，待实现计划审阅  
**部署目标：** 单 EC2 后端（Cloud API、Translator Agent、PostgreSQL、SMTP）  
**第一期目标：** 用户以用户名、邮箱、密码和 6 位邮箱验证码完成注册；未验证信息不创建正式用户。

## 1. 背景与范围

当前注册接口会直接创建用户及试用权益，Android 表单仍沿用手机号字段。第一期改为邮箱验证码注册，并保持后端全部运行在 EC2：

```text
Android
  └─ HTTPS → Caddy → Cloud API (127.0.0.1:8080)
                         ├─ PostgreSQL 17 (127.0.0.1:15432)
                         └─ SMTP submission (127.0.0.1 only)
                                      └─ Internet recipient mailbox
```

包含：

- 用户名 + 邮箱 + 密码 + 6 位验证码注册；
- 自建 SMTP 出站投递真实邮箱；
- 验证码与请求反滥用限制；
- Android 注册两步界面和错误状态；
- 旧用户登录、token、账户中心兼容。

不包含：

- 手机号/SMS 验证；
- 域名购买、MX/SPF/DKIM/DMARC/PTR 配置；
- 邮件营销、密码找回、邮箱变更验证；
- 多 EC2、Redis、队列或第三方邮件服务。

无域名阶段允许以 EC2 公网 IP 尝试真实投递；应明确接受部分邮箱服务商拒收、延迟或进入垃圾箱。后续有域名后仅替换 SMTP 主机名及 DNS/签名配置，不变更验证码 API 或数据库业务模型。

## 2. 方案选择

采用“**验证成功后才创建正式用户**”，不采用 pending 用户。

```text
注册信息提交
  → 创建/更新待验证注册记录
  → 生成并投递验证码
  → 用户输入验证码
  → 在事务中创建 user + password credential + trial entitlement
```

优势：

- 未验证记录不会占用正式用户、邮箱或权益；
- 未验证注册过期后可安全删除；
- 登录和既有正式用户表不引入 pending 状态分支；
- 试用权益只会授予完成邮箱验证的用户。

## 3. 数据模型

新增 `registration_verifications` 表（名称可随现有 migration 命名约定调整）：

| 字段 | 说明 |
|---|---|
| `id` | UUID 主键 |
| `username` | 已规范化的候选用户名 |
| `email` | 已规范化的候选邮箱 |
| `password_hash` | 密码哈希；不存明文密码 |
| `code_hash` | 验证码哈希；不存验证码明文 |
| `code_salt` | 每次验证码独立随机 salt，或等价安全实现 |
| `expires_at` | 创建后 10 分钟过期 |
| `attempt_count` | 当前验证码验证尝试次数 |
| `sent_at` | 最近一次发送时间，用于 60 秒冷却 |
| `hour_bucket` | 邮箱发送限流时间桶，或由独立审计表计算 |
| `created_at` / `updated_at` | 审计与清理 |

建议约束和索引：

- 对规范化 `email` 设置唯一活跃验证记录语义（通过 upsert/事务实现）；
- `expires_at`、`email`、`created_at` 索引，支持限流与过期清理；
- 记录只保留必要注册材料，完成/过期后删除；
- 不记录完整验证码、明文密码、SMTP 密码、JWT、DSN 或完整邮件正文。

另建或复用轻量 `email_verification_rate_limits` 表记录不可逆/可过期的发送计数：

- key 类型：`email`、`ip`；
- key 值：规范化邮箱或 IP 的 keyed hash，避免在限流表额外保留可直接识别信息；
- `window_started_at`、`request_count`、`updated_at`。

不使用 Redis。PostgreSQL 事务与行级锁保证单 EC2 初期的原子限流。

## 4. API 契约

### 4.1 请求注册验证码

```text
POST /api/v1/auth/registration-verifications
```

请求：

```json
{
  "username": "example_user",
  "email": "user@example.com",
  "password": "..."
}
```

行为：

1. 校验用户名、邮箱、密码格式和长度；
2. 检查正式用户的用户名/邮箱冲突；
3. 应用邮箱/IP 限流；
4. 生成密码学安全随机 6 位数字验证码；
5. 只存验证码哈希和候选密码哈希；
6. 经本机 SMTP 投递邮件；
7. 成功返回 `202 Accepted` 与最短可重发等待秒数。

为避免邮箱枚举，已注册邮箱、受限邮箱、发送失败的外部可见响应尽量统一为 `202`；内部以脱敏 reason 和 request ID 记录。对用户名冲突可在最终验证时返回冲突，或采用同样的通用响应，具体以现有 UX 一致性实现。

### 4.2 确认验证码并完成注册

```text
POST /api/v1/auth/registration-verifications/confirm
```

请求：

```json
{
  "email": "user@example.com",
  "code": "123456"
}
```

行为：

1. 查找尚未过期的待验证记录；
2. 原子增加尝试计数；
3. 在 5 次内验证验证码哈希；
4. 验证成功后同一事务创建正式用户、密码凭据、试用权益；
5. 删除待验证记录及相关临时限流状态；
6. 返回与现有注册成功等价的公开用户/试用权益结构。

失败语义：

- 验证码错误、过期、已消耗统一返回不可验证错误，避免泄露记录存在性；
- 第 5 次失败后使当前验证码失效，要求重新发起；
- 最终创建时的用户名/邮箱冲突返回冲突错误，不创建部分数据；
- SMTP 失败不创建验证码记录或将其标为不可用，避免发送未成功却可猜测的验证码。

### 4.3 旧接口兼容

现有 `POST /api/v1/auth/register` 不再由 Android 调用。第一期可保留为受控兼容入口或返回迁移错误，最终由实现计划确定；它不得继续绕过邮箱验证创建新账号。

已有用户和现有 refresh/access token 保持兼容；登录仍支持当前已发布的兼容路径，直到单独完成“用户名/邮箱登录、移除手机号”的认证收敛变更。

## 5. 反滥用与安全

| 控制项 | 规则 | 实现 |
|---|---|---|
| 验证码长度 | 6 位数字 | `crypto/rand`，禁止伪随机/时间种子 |
| 有效期 | 10 分钟 | 服务端 `expires_at` 判定 |
| 验证码存储 | 仅哈希 + 每次随机 salt | 比较使用常量时间语义 |
| 单邮箱冷却 | 60 秒 | 最近 `sent_at` 判定 |
| 单邮箱发送上限 | 5 次/小时 | keyed hash 的邮箱桶 |
| 单 IP 发送上限 | 20 次/小时 | 从可信反代客户端 IP 提取；未配置可信代理时 fail closed/仅使用直接地址 |
| 单验证码尝试 | 最多 5 次 | 行级锁内递增；达到上限失效 |
| 请求体 | 小上限、严格 JSON | 复用 Cloud API body limit |
| 审计 | request ID、聚合原因、状态码 | 不记录验证码、密码、token、完整邮箱、SMTP 认证信息 |

Caddy 仅应把真实客户端 IP 传递给 Cloud API；Cloud API 只信任由本机 Caddy 注入/转发链明确声明的 IP header，不能信任任意客户端伪造的 `X-Forwarded-For`。

## 6. SMTP 自建服务

### 6.1 运行边界

EC2 部署 Postfix（或等价成熟 MTA）：

- SMTP submission 只监听 `127.0.0.1`；
- Cloud API 只通过回环 `localhost` 投递；
- 不开放 `25`、`465`、`587` 入站给公网；
- 禁止 open relay；
- 服务由 systemd 管理，限制最小权限；
- SMTP 配置、队列和日志不进入 Git。

Cloud API 通过独立邮件发送接口/adapter 调用 SMTP。邮件模板只含产品名、验证码、10 分钟有效提示和安全说明；不回显密码、token、完整客户端 IP 或内部地址。

### 6.2 无域名测试限制

临时使用 EC2 公网 IP/本机 hostname 进行 HELO 和投递尝试。需要在实施时验证：

- EC2 是否允许出站 `25/tcp`；
- 目标邮件服务商是否接受该来源；
- Postfix 队列、退信和日志是否正常。

投递不可用时，注册请求应以可重试的通用错误失败，不能伪造“邮件已发送”。不允许在日志或 Android UI 显示验证码替代邮件投递。

### 6.3 域名上线迁移

获得域名后：

- 设置 `myhostname` 和发件地址；
- 添加 SPF；
- 配置 DKIM 签名；
- 添加 DMARC；
- 向 EC2/IP 提供方申请 PTR；
- 重新验证 Gmail/QQ 等投递与垃圾箱表现。

验证码 API、数据库表、Android 流程和限流规则保持不变。

## 7. Android 注册体验

注册改为两步：

1. **填写资料**：用户名、邮箱、密码、确认密码；点击“发送验证码”。
2. **邮箱验证**：显示脱敏邮箱、6 位验证码输入、倒计时重发、确认注册。

要求：

- 移除新注册手机号输入、手机号校验和手机号验证码 UI；
- 不在 ViewModel 持久化明文密码或验证码；提交后尽快清空密码和验证码；
- 重发按钮在 60 秒内禁用，服务端限制是最终权威；
- 失败提示不回显完整邮箱、验证码或服务端敏感内容；
- 网络/邮件投递失败可安全重试；
- 注册完成后沿用现有成功状态与登录/账户刷新行为；
- 登录页改为用户名/邮箱 + 密码；旧手机号登录兼容策略与本变更分离，除非实现中必须移除其 UI。

## 8. 测试与验收

### Cloud API

- 6 位随机码格式、哈希存储、10 分钟过期；
- 正确/错误/过期/第 5 次失败；
- 60 秒冷却、邮箱 5 次/小时、IP 20 次/小时；
- 并发发码、并发确认时只创建一个正式用户与一份权益；
- 正式邮箱/用户名冲突与枚举安全响应；
- SMTP 成功、临时失败、永久失败；
- 不发送真实邮件的 fake sender 单元测试；
- 安全 PostgreSQL integration 测试仅使用 `127.0.0.1:15432`。

### SMTP/EC2

- SMTP 仅监听回环；
- 公网 `25/465/587` 不可达；
- Cloud API 可投递一封测试验证码至真实测试邮箱；
- 检查邮件队列和日志不含验证码/密码；
- 确认 EC2 出站端口受限或被 AWS 拦截时有明确运维错误。

### Android

- 表单校验、发送/重发倒计时、验证码确认；
- 错误状态与敏感字段清理；
- Cloud API 请求契约；
- `testDebugUnitTest`、`lintDebug`、`assembleDebug`；
- 真机真实邮箱收件与注册完成 smoke。

## 9. 风险与限制

- 没有域名、SPF/DKIM/DMARC/PTR 时，真实邮箱投递不可靠；这是第一期明确接受的限制。
- EC2 可能限制出站 25 端口；如受限，需向 AWS 申请解除或后续使用可配置 smarthost，但不降低验证码安全要求。
- 单 EC2 的 SMTP、API、数据库仍是单点；本变更不提供高可用。
- PostgreSQL 限流在单节点充分；未来横向扩展时需迁移为共享限流存储。

# 共享年度邀请码（旧 App 兼容）

`POST /api/v1/redemptions` 请求/响应不变，沿用四段六码的现有格式和大小写归一规则，无需升级 App。现有单次码仍全局一次并顺延权益；共享码每账号一次，领取时立即获得365天，保留原权益。

## 数据与安全

迁移 `000015_shared_redemption_codes`：码保存哈希，增加shared/claim_expires_at；redemption_claims以(code_id,user_id)唯一，权益与领取同事务提交。账号行锁串行重复领取；批次共享锁与停用串行。过期在账号锁取得后再次核对数据库时钟，截止时刻不接受。删除账号沿用禁用/匿名化，不删除领取痕迹。

只有运维CLI可签发共享码，不增加公开签发API。后台原批次停用操作可停止未来领取，不撤销已发权益。原批次计数仍是码数量，不是共享领取人数；统计领取须查询redemption_claims，不能把“未使用码”计数理解成无人领过。

邀请码可能被传播；无全局人数限制不代表防滥用。须使用已认证账号，原HTTP限流保留。禁止码原文、账号凭据、数据库URL进入Git/日志。

## 创建指定内部活动

在受控服务器上，通过环境变量SHARED_INVITE_DATABASE_URL提供显式127.0.0.1:15432 PostgreSQL配置，不把凭据放命令参数。管理员UUID必须为现有启用管理员。

```bash
umask 077
shared-invite -admin-id <admin-uuid> -name internal-beta-2026 \
  -claim-until 2027-01-01T00:00:00+08:00 -output <new-private-delivery-file>
```

输出文件不可已存在，权限600；stdout仅批次ID、截止时间和365天，不输出码。仅在CLI成功、批次与hash核验后分发文件中的码；CLI失败时文件可能含未激活码，切勿分发，先核对状态。

本活动独占截止为北京时间2027-01-01 00:00，即UTC2026-12-31 16:00。截止只影响后续领取，已领取者继续持有其365天权益。CLI可用于不同活动，参数不硬编码本活动日期。

## 验证与回滚

专用隔离PG位于127.0.0.1:15432，不能对生产运行测试。定向回归：

```bash
cd cloud-api
go test ./...
go vet ./...
go test -tags=integration -count=1 -run 'TestShared(Redemption|Invite)' ./integration
```

真实数据库回归需提供CLOUD_API_TEST_DATABASE_URL，否则跳过不能视为验证通过。覆盖多用户、重复/10并发、截止边界及跨锁等待截止、停用、旧码单次顺延、旧权益保留及签发。token/码均随机测试夹具，不记录实际生产码。

部署前备份数据库、当前二进制与原迁移目录；用校验账本的migrate up应用增量，再更换API二进制并重启。旧二进制不识别shared字段，会尝试按单次码消费共享码，数据库约束会拒绝，但不能继续提供共享码服务；回滚应用时先停用共享批次，保留新增表与领取数据。down迁移在已存在共享码/领取记录时拒绝执行，不能删除真实领取数据以求回滚。

不得在真实用户账号上自动消耗邀请码验证；生产验证使用只读元数据及健康检查。端到端领取行为以隔离数据库验证为主，用户实际首次领取后再核对。
